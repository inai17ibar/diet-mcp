# 本人向けの定期振り返り

食事の既存MCPツール get_daily_summary / get_week_summary は、健康データをhealthに含める。
引数は従来のまま。RESTの /api/summary/daily と /api/summary/week は食事のみを返す。
SNS処理へ体重データを混ぜないため、MCP専用のreview_toolsで組み立てる。

health.daily は日付、歩数、活動エネルギーkcal、その日の体重平均、測定件数、活動取込時刻。
healthの平均は記録のある日だけが分母。体重は日内平均→期間平均。欠測はnull。
latest_weight_measurement は取得対象期間内の実測のみ。過去値を毎日に補完しない。

## 自動振り返りの方針

- 毎朝、前日を短く振り返る。日曜日は直近7日、毎月1日は前月、1/4/7/10月1日は前3か月も同じレポートに加える。
- 月次・3か月は複数の週サマリから対象日を抽出して重複日を除く。期間外の日は含めない。
- 食事・歩数・体重それぞれの記録日数、期間、欠測、最新測定日、同期の鮮度を明示。
- 食事なしは0kcalと解釈しない。食事ありも全食記録済みとは保証しない。
- 体重単日の上下で食事制限を強めない。十分な測定のある複数週の傾向を使う。
- 歩数や活動エネルギーは総消費カロリーではない。観察された関係から因果や正確な維持カロリーを断定しない。
- 保存済み目標と提案中の目標を分け、設定を自動変更しない。
- 今日できる小さな行動を1つに絞る。欠食や罰の運動、記録のない日の数値補完を提案しない。
- 取得不能時は対象期間と不足項目を短く報告し、以前のデータで最新結果を装わない。

新しい接続や再認証が必要なら、先に接続を済ませてからスケジュールを有効にする。
