# Apple Health → diet-mcp: 準備と実機検証

このブランチは受信APIと本人向け週次集計の準備。デプロイ、iPhone設定、キー発行は未実施。
食事目標は変更しない。体重は既存の食事サマリやInstagram生成には追加しない。

## サーバー設定（本番反映時）

1. SQLite Volumeをバックアップする。
2. 専用のランダムな `DIET_HEALTH_IMPORT_TOKEN` をシークレットとして設定する。
   ログイン用 `DIET_MCP_API_KEY` と必ず別にする。未設定なら取込は401。
3. レビュー後にデプロイし、下記の手動テストをする。
   mainへのpushは既存ワークフローで自動デプロイされるので、準備段階ではマージしない。

## API（提案ではなく、このブランチで実装した契約）

`POST /api/health/import`
`Authorization: Bearer <DIET_HEALTH_IMPORT_TOKEN>`、Content-Type: application/json

```json
{
  "daily": [
    {"date": "2026-11-13", "steps": 5300, "active_energy_kcal": 320}
  ],
  "weights": [
    {"measured_at": "2026-11-13T07:00:00+09:00", "weight_kg": 95.0}
  ]
}
```

- 日付はJSTで区切る。歩数は日別の合計、活動エネルギーはkcal、体重はkg。
- 日別31件・体重500件まで、256KB上限。通常は過去7日分を再送する。
- 日別値は置換、体重はUTCに正規化した測定日時で更新。再送で加算されない。
- 取得できなかった項目は送らない（nullも既存値を保持）。0は実測の0だけ。
- 体重は新しい測定だけを送る。最新の体重を毎日の測定として複製しない。
- 体重サンプルの削除・測定日時の変更の伝搬は未対応。
- 同じバッチ内の日付/体重測定日時重複は400。全件検証してから一括保存。
- iPhone側は同時実行を避け、直列に送信する。古い取得結果を後から送ると上書きされる。

`GET /api/health/week?date=2026-11-13`
`Authorization: Bearer <DIET_MCP_API_KEY>`（専用取込トークンでは読めない）

月〜日のJST集計、日別値、項目別記録日数と平均、食事の記録日平均を返す。
欠測はnull。体重は日内平均を求めてから週平均を出す。食事の記録日は全食記録済みとは限らない。
活動エネルギーは基礎代謝を含む総消費量ではない。摂取量との差から減量予測は行わない。

## iPhoneショートカットの作成手順

署名済みshortcutファイルは未作成。以下の手順で端末上に作成する。

1. 新規ショートカット「健康データを同期」を作成。
2. 過去7日を日ごとに繰り返し、JSTの0時〜翌0時で「ヘルスケアサンプルを検索」。
3. 歩数・アクティブエネルギーを日別集計して上記のdaily辞書を作る。
   iPhoneとWatchの生サンプルを単純合計しない。まずWatchだけに絞るなどソースを明示し、
   ヘルスケアの日別表示と比較する。Watchだけの場合は非装着時のiPhone歩数を含められない。
   **数日比較して一致する集計が作れなければ、歩数の自動送信は有効にしない。**
   その場合は体重だけで開始し、HealthKit統計を利用できるiOSアプリ/エクスポート手段に切り替える。
4. 同期間の体重を取得し、各サンプルの実測日時（タイムゾーン付きISO 8601）とkgをweightsにする。
5. 「URLの内容を取得」で上記POSTへJSONを送る。専用トークンをAuthorizationヘッダーに設定。
   トークン入りショートカットを公開共有しない。
6. 200応答を確認して成功を表示する。エラー時は成功扱いにしない。
7. 手動実行で検証後、オートメーションの「ChatGPTを開いたとき」に紐付ける。
   頻発を防ぐため前回成功から数時間以内なら終了するチェックを加える。
   成功時だけ前回成功時刻を更新。失敗時は次回に同じ7日分を再送する。

ロック中はHealthKitが読めないことがあるため、完全な定時無人同期は保証しない。

## 実機で確認すること

- 初回の読み取り許可、拒否時に0で上書きしないこと。
- Watch/iPhone重複、非装着日、日付境界を含む3日以上で画面と照合。
- 連打・ネット切断・再送でもレコード数と合計が増えないこと。
- 測定なしの日がnullになること、kg/kcalの単位。
- 専用APIの取得結果を確認し、既存SNS画像に体重が出ないこと。
